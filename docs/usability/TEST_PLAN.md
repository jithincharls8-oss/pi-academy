# PI Academy: 10-minute usability test

Run this with 3 to 5 colleagues who work with PI or want to learn it. One person at a time, on their
own laptop, with the installed app or the web version. You watch and take notes; you do not help
unless they are stuck for more than a minute. Afterwards they fill in the SUS questionnaire below.

The test checks the redesign's main claim: a new learner can tell what to do next, learn something,
check it, and use a PI tool mockup without help.

## Before you start (1 minute)

Say: "I'm testing the app, not you. Please think out loud. There are no wrong answers."
Start from a fresh profile (Settings > Backup and restore > Reset) so every tester sees the new-user state.

## Tasks (8 minutes)

Write down, for each task: completed yes/no, time taken, and anything they hesitated over or said.

| # | Say to the tester | Success looks like | Target |
|---|---|---|---|
| 1 | "You've just opened this. What would you do first?" | Points at or clicks the next lesson on Home without searching | 15 s |
| 2 | "Start that lesson and read until the first diagram." | Opens the lesson, scrolls to the Diagram section | 90 s |
| 3 | "Answer the lesson's knowledge check." | Answers all three questions and sees feedback after each | 2 min |
| 4 | "How many days is your streak, and how do you start one?" | Reads the streak in the top bar or Home and opens the Daily Exam | 30 s |
| 5 | "Open the PI System Management Tools mockup and look at the last hour of values for a pump flow tag." | Opens the Sandbox, then SMT, then Archive Editor, and gets rows in the grid | 2 min |
| 6 | "Go back to the main app." | Uses the "PI Academy" back link in the top-left | 15 s |
| 7 | "Find what the PI term 'CompDev' means." | Uses search (Ctrl K) or the Reference glossary | 45 s |

## Debrief (1 minute)

Ask: "What was the most confusing moment?" and "What would make you open this again tomorrow?"

## SUS questionnaire

The System Usability Scale (Brooke, 1996). Each item is scored 1 (strongly disagree) to 5
(strongly agree).

1. I think that I would like to use this system frequently.
2. I found the system unnecessarily complex.
3. I thought the system was easy to use.
4. I think that I would need the support of a technical person to be able to use this system.
5. I found the various functions in this system were well integrated.
6. I thought there was too much inconsistency in this system.
7. I would imagine that most people would learn to use this system very quickly.
8. I found the system very cumbersome to use.
9. I felt very confident using the system.
10. I needed to learn a lot of things before I could get going with this system.

### Scoring

For odd items, subtract 1 from the answer. For even items, subtract the answer from 5. Add the ten
results and multiply by 2.5. That gives a score from 0 to 100 for each tester; average them.

As a rough guide from published SUS benchmarks, about 68 is average, and 80 or more is in the top
range. Treat any task that fewer than 4 of 5 testers complete as a design bug to fix, whatever the SUS
score.
