### adm.install-upgrade: PI Server install kit, order, prerequisites, upgrade paths

**Facts**
- OSIsoft's implementation guidance gives this install order: "1. Install Microsoft SQL Server. 2. Install the AF server using the PI Server install kit. 3. Install any instances of Data Archive." [S:adm-implementation-adoption] (read)
- For a PI Data Archive collective, "you must first perform the installation and post-installation tasks on the primary server." [S:adm-implementation-adoption] (read)
- Data Archive installation is described in four phases: pre-installation, installation, post-installation, and connecting an interface. [S:adm-implementation-adoption] (read)
- The 2024 Architecture course lists these pre-install steps: confirm the installer account is an administrator with Write permission to MS SQL Server and Windows is updated; install SQL Server and confirm its service is running; check the OS clock and time zone; generate the Machine Signature File and obtain the license file; then run the PI Server installer as administrator. [S:adm-arch-planning-workbook-2024] (read)
- "A License File must be generated before the PI Data Archive server is installed"; the Machine Signature File (MSF) is generated by the install kit on the target machine. [S:adm-arch-planning-workbook-2024] (read)
- Setup copies the license file to `%PISERVER%\dat`, and the original file is no longer used. [S:adm-arch-planning-workbook-2024] (read)
- "Ensure the MS SQL Server service is started before installation." [S:adm-arch-planning-workbook-2024] (read)
- "AVEVA recommends that you install MS SQL Server on a different computer from PI Server." [S:adm-arch-planning-workbook-2024] (read)
- "In your work environment, all clocks should be synchronised from a network time source", and "Changing the clock after installation will cause problems." [S:adm-arch-planning-workbook-2024] (read)
- The 2024 course lists Windows Server 2022 (recommended), 2019 and 2016, full or Core installation, for production; Windows 10 only for test systems. [S:adm-arch-planning-workbook-2024] (read)
- Software versions in the 2024 course: PI Data Archive 2024 (3.5.505.1040), PI AF Server 2024 (3.1.0.1177), PI Vision 2024 (3.10.0.0), PI Buffer Subsystem 2018 SP2 Patch 2 (4.9.0.37). [S:adm-arch-planning-workbook-2024] (read)
- Disk requirements in the course: PI Data Archive and PI SDK 160 MB plus 100 MB temporary space during installation; Data Archive databases 11 MB per 1,000 points plus 1 MB; message log files 10 MB; archive files 10 MB per 1,000 points; event queue 5 MB per 1,000 points. [S:adm-arch-planning-workbook-2024] (read)
- An upgrade rollback backup needs space equal to the PI Data Archive databases plus the primary archive. [S:adm-arch-planning-workbook-2024] (read)
- In the installer you select features, directories, the SQL instance and gMSA accounts; after installation you stop PI Data Archive with `pisrvstop.bat`, switch the PI Network Manager service to the gMSA, and restart. [S:adm-arch-planning-workbook-2024] (read)
- Example gMSA assignments in the course: `SVC-PIDA$` (PI Network Manager), `SVC-PIAF$` (AF Application Service), `SVC-PIANALYT$` (PI Analysis Service), `SVC-PICON$` (PI to CONNECT Agent). [S:adm-arch-planning-workbook-2024] (read)
- gMSA names must be fewer than 15 characters, and "By default, it takes 10 hours until the KDS Root Key is in effect". [S:adm-arch-planning-workbook-2024] (read)
- The PI Buffer Subsystem Buffering Manager accepts a gMSA starting at version 4.9.0.37; older versions need the gMSA added to the local PI Buffering Administrators group. [S:adm-arch-planning-workbook-2024] (read)
- OSIsoft's PowerShell install sample (v1.0.8) was tested with SQL Server 2017 Express and PI Server 2018 SP3 Patch 1, and states that SQL Server Express "must be running locally in order to install the PI Server" when using that script. [S:adm-github-pi-core-deploy-onprem] (read)
- PI Server 2018 SP3 and Patch 1 require .NET Framework 4.8, which "must be installed before running" the install; the .NET install usually needs a restart. [S:adm-github-pi-core-deploy-onprem] (read)
- The sample's `-piserver` option uses the TYPICAL feature set, which includes PI Data Archive, PI AF Server and supporting products, and uses the `silent.ini` extracted from the install kit when none is given. [S:adm-github-pi-core-deploy-onprem] (read)
- Example silent install command from the sample: `.\Install-PIServer.ps1 -sql .\SQL\SETUP.EXE -piserver .\PIServer.exe -pilicdir C:\Test -afdatabase TestDatabase -pibundle .\PIProcessBook.exe -remote`. [S:adm-github-pi-core-deploy-onprem] (read)
- The sample's verification script checks that SQL Server Express (instance SQLExpress) is running, the PI Archive Subsystem is running and the AF database exists. [S:adm-github-pi-core-deploy-onprem] (read)
- SQL Server Express limits cited by OSIsoft: single-threaded, 10 GB database size, 1 GB RAM, and no AF audit tables. [S:adm-uc15-af-batke] (read)
- "The MS SQL Express Edition is limited to using only a single physical CPU and 1 GB of RAM." [S:adm-arch-planning-workbook-2024] (read)
- After an install, the course says to search the message logs for errors (Operations > Message Logs) and check Operation > PI Services and Operation > Archives in PI SMT. [S:adm-arch-planning-workbook-2024] (read)
- A PI Server 2018 SP3 install creates no default points, although the install guide (page 90, "Verify PI Data Archive is updating Data for default Tags") said to check them; AVEVA said the documentation team would update it. [S:adm-feedback-pida-i-1306] (read)
- Moving a PI Data Archive to a new server currently requires installing the same software version and then restoring from a backup of the old server, according to a 2025 AVEVA feedback idea. [S:adm-feedback-pida-i-1108] (read)
- PI Server 2018 SP3 continued to get bug and security fixes as patches. The UC23 deck called 2018 SP3 Patch 5 current; later bulletins name Patch 6, 7 and 8 as fixes. [S:adm-uc23-security-biggins] [S:adm-aveva-bulletin-2026-002] (read)
- AVEVA bulletins label the PI Server 2018 SP3 line "(Core)" and 2023/2023 SP1 "(Hybrid)". [S:adm-aveva-bulletin-2025-001] (read)
- Security fixes define minimum upgrade targets: 2023 Patch 1 or 2018 SP3 Patch 6 for AVEVA-2024-001; 2024 or 2018 SP3 Patch 7 for AVEVA-2025-001; 2024 R2 or 2018 SP3 Patch 8 for AVEVA-2026-002. [S:adm-aveva-bulletin-2024-001] [S:adm-aveva-bulletin-2025-001] [S:adm-aveva-bulletin-2026-002] (read)
- "A medium sized PI System installation would be quoted at under 5 days by OSIsoft field service." [S:adm-implementation-adoption] (read)
- AF 2015 (version 2.7) and later use Windows integrated authentication with AF identities and mappings. [S:adm-implementation-adoption] (read)
- Since Data Archive 2012, automatic archive creation has been enabled by default; before 2012 the default historic archive size was 256 MB. [S:adm-it-pros-workbook-2017r2] (read)
- Data Archive 2015 introduced future data, with timestamps from January 1970 through January 2038. [S:adm-it-pros-workbook-2017r2] (read)

**Terms**
- Machine Signature File (MSF): file generated by the install kit on the target server and used to obtain the PI Data Archive license file before installation [S:adm-arch-planning-workbook-2024]
- pilicense.dat: the PI Data Archive license file that the install script expects [S:adm-github-pi-core-deploy-onprem]
- gMSA (group Managed Service Account): AD account type with managed passwords that the course uses for PI Network Manager, AF, Analysis and buffering services [S:adm-arch-planning-workbook-2024]
- silent.ini: the answer file the PI Server install kit uses for unattended installs [S:adm-github-pi-core-deploy-onprem]

**Worked-example material**
- Course lab topology: PISRV01 and PISRV02 (a PI collective), PIINT01 and PIINT02 (interface nodes), PIDC (domain controller). [S:adm-arch-planning-workbook-2024]
- Lab paths (lab values, not recommendations): Historical Archives `E:\PIArchives`, future archives `E:\PIArchives\future`, Event Queues `E:\PIEventQ`. [S:adm-arch-planning-workbook-2024]
- Default paths: 64-bit clients under `Program Files\PIPC`, Data Archive under `Program Files\PI`, archives under `\PI\arc`, future archives `\PI\arc\future`, event queues `\PI\queue`. [S:adm-arch-planning-workbook-2024]

**Common mistakes / pitfalls**
- Installing Data Archive before AF/SQL breaks the recommended order (SQL, then AF, then Data Archive). [S:adm-implementation-adoption]
- Changing the server clock after installation causes problems. [S:adm-arch-planning-workbook-2024]
- Forgetting .NET 4.8 (with its restart) before running the 2018 SP3 kit. [S:adm-github-pi-core-deploy-onprem]
- Expecting default health points after a 2018 SP3 install: none are created. [S:adm-feedback-pida-i-1306]

**Open questions**
- The official docs.aveva.com install-order pages and the exact supported SQL Server versions per PI Server release could not be read. [S:adm-docs-af-preinstall]
- Exact supported upgrade paths (for example, the minimum source version for an in-place upgrade to 2024) were not found.

### adm.sizing: hardware sizing, archive storage

**Facts**
- AVEVA does not publish Data Archive CPU/RAM figures in the course; new systems are sized with the Customer Success Manager and Account Manager, and existing systems through technical support. [S:adm-uc23-da-performance-sick] [S:adm-arch-planning-workbook-2024] (read)
- OSIsoft said "hardware sizing should be based upon workload, not AF object count, because they do not correlate", and pointed to the Hardware and PI System Sizing Recommendations spreadsheet. [S:adm-implementation-adoption] (read)
- "There is no hardware sizing tool for interface machines." [S:adm-implementation-adoption] (read)
- Collective members "should be identical in the case of a collective and can be in different data centers." [S:adm-implementation-adoption] (read)
- Archive sizing in the 2017 R2 IT course: (Physical Memory MB) ÷ 3 or 3 × (Licensed Point Count)/1024 MB, whichever is smaller, rounded down to a power of 2, minimum 256 MB and maximum 10,240 MB. [S:adm-it-pros-workbook-2017r2] (read)
- The 2024 course says "Archives are sized with at least 2KB for each point in the system"; default is 3 KB × total points rounded to a power of 2, with a 10 GB cap. [S:adm-arch-planning-workbook-2024] (read)
- 2024 course table by licensed points: 0–87,381 → 256 MB; 87,382–174,762 → 512 MB; 174,763–349,525 → 1,024 MB; 349,526–699,050 → 2,048 MB; 699,051–1,398,101 → 4,096 MB; 1,398,102–2,796,202 → 8,192 MB; 2,796,203 or more → 10,240 MB. [S:adm-arch-planning-workbook-2024] (read)
- 2024 course table by physical memory: 0–1,535 MB → 256 MB; 1,536–3,071 → 512; 3,072–6,143 → 1,024; 6,144–12,287 → 2,048; 12,288–24,575 → 4,096; 24,576–30,719 → 8,192; 30,720 or more → 10,240 MB. "Select a size so that at least 2 archive files can fit in the Windows File System Cache." [S:adm-arch-planning-workbook-2024] (read)
- The UC23 performance deck recommends enough RAM to hold three archives, with each archive file no larger than a third of system RAM. [S:adm-uc23-da-performance-sick] (read)
- The OS caches 256 KB sections of files read from disk. [S:adm-uc23-da-performance-sick] (read)
- "Lower latency storage has a greater impact on performance queries than having more IOPS." [S:adm-uc23-da-performance-sick] (read)
- Place archives on the largest drive and event queues on the second-largest. AVEVA recommends the event queue be on a different physical drive from the archives. [S:adm-arch-planning-workbook-2024] (read)
- A 2010 OSIsoft optimisation deck estimated storage at "est. 5-20 bytes per event" and memory at "2GB minimum, up to 8KB per point". [S:adm-vl2010-optimization] (read)
- The 2010 deck recommended no points with more than about 10 index records, and listed common read:write ratios above 5:1. [S:adm-vl2010-optimization] (read)
- PI Server 2012 Standard Edition tiers (2012 keynote): XS 50K points / 10K write EPS / 1 GB RAM; S 250K / 50K / 4 GB; M 1M / 200K / 16 GB; L 5M / 500K / 64 GB; XL 20M+ / 1M+ / 256 GB. Write EPS assumes 50% compression. [S:adm-vcl12-pi-server-2012-keynote] (read)
- The same tiers list data per month: XS 75 GB, S 375 GB, M 1.5 TB, L 3.75 TB, XL 7.5 TB; and concurrent apps 5, 10, 50, 250, 1,000+. [S:adm-vcl12-pi-server-2012-keynote] (read)
- In a 2012 lab test on 6 vCPU / 12 GB VMs, PI Server 2010 sustained 150K EPS writes (10K points at 15 Hz) and PI Server 2012 sustained 600K EPS (10K points at 60 Hz). [S:adm-vcl12-pi-server-2012-keynote] (read)
- The 2017 PI System Basics deck lists Data Archive figures: maximum tag count 20M+; startup under 30 s per million tags; data out (archive) over 10M events/s; data in (snapshot) over 1M events/s; data in (archive) over 500K events/s. [S:adm-pi-system-basics-2017] (read)
- A 2008 deck listed 1,000–2,000,000 data streams on 32-bit and 1,000–10,000,000 on 64-bit, and about 15 µs timestamp resolution. [S:adm-uc2008-servers-batke] (read)
- Separate PI AF and PI Data Archive computers are recommended when AF uses data from multiple PI Servers or is configured for high availability. [S:adm-arch-planning-workbook-2024] (read)
- For large distributed systems, AVEVA recommends PI Data Archive collectives, two PI AF Servers behind a Network Load Balancer, and SQL Server on separate redundant computers. [S:adm-arch-planning-workbook-2024] (read)
- For the AF SQL Server, OSIsoft recommends more RAM and fast disks, and segregating PI Data Archive, AF Server, SQL Server and PI Analysis Service by performance and IT requirements. [S:adm-uc15-af-batke] (read)
- "AF Server never talks to PI Data Archive", so the client-to-server connection is what to optimise; network latency between client and server affects performance. [S:adm-uc15-af-batke] (read)
- The PI Buffer Subsystem buffer queue file defaults to 32 MB, and more files are created as each fills. [S:adm-it-pros-workbook-2017r2] [S:adm-pdfcoffee-pi-sys-admin-2018sp2] (read)
- Future archives start at 1 MB with a one-calendar-month span and grow dynamically beyond 1 MB. [S:adm-arch-planning-workbook-2024] [S:adm-it-pros-workbook-2017r2] (read)
- A new historic archive is created when the current one is about 98% full. [S:adm-it-pros-workbook-2017r2] (read)
- Archives are fixed size by default; dynamic archives are only for troubleshooting and reprocessing. [S:adm-it-pros-workbook-2017r2] (read)
- PI Server 2024 improves out-of-order writes by up to 40% for numeric types and up to 90% for strings and blobs ("Your mileage may vary"). [S:adm-uc23-da-performance-sick] (read)
- Throughput figures for PI Web API ingestion (for example 4–9k events/s) are user estimates in a PI Square thread, and an AVEVA community expert said they "appear way too few". [S:adm-pisquare-webapi-eps] (read)

**Terms**
- Hardware and PI System Sizing Recommendations spreadsheet: OSIsoft sizing tool referred to for Data Archive and AF hardware [S:adm-implementation-adoption]
- Archive_AutoArchiveFileSize: tuning parameter for the size of the new primary archive on an automatic shift [S:adm-uc23-da-performance-sick]

**Worked-example material**
- A 600,000-point system with 32 GB RAM: point rule gives 3 × 600,000 / 1024 ≈ 1,758 MB, rounded down to 1,024 MB; memory rule gives 32,768 / 3 ≈ 10,922 MB. Under the 2017 R2 "smaller of the two" rule, the archive is 1,024 MB. (Under the 2024 table, 600,000 points falls in the 2,048 MB row, so the two course versions differ.) [S:adm-it-pros-workbook-2017r2] [S:adm-arch-planning-workbook-2024] (inferred)
- The course exercise sets `Archive_AutoArchiveFileSize` to 512 MB and `Archive_AutoArchiveFileRoot` to `E:\PIArchives\PISRV01`. [S:adm-it-pros-workbook-2017r2]

**Common mistakes / pitfalls**
- Running AF on SQL Express in production: 10 GB DB cap, 1 GB RAM, no audit trail. [S:adm-uc15-af-batke]
- Sizing AF hardware by object count instead of workload. [S:adm-implementation-adoption]
- Archives too large to fit in the file cache. [S:adm-uc23-da-performance-sick]

**Open questions**
- PI Vision server sizing figures (users per server, CPU/RAM) were not found in any readable source.
- AF Server/SQL sizing numbers per element count were not found.
- The 2024 workbook's text says the archive minimum is 512 MB but its table starts at 256 MB; mark `verify`. [S:adm-arch-planning-workbook-2024]
- Bytes-per-event (5–20) is from a 2010 deck; current value unverified.

### adm.naming: tag naming and AF naming

**Facts**
- PI Server guidance (quoted on PI Square from the System Management Guide): "The first character must be alphanumeric, an underscore (_), or a percent sign (%)." [S:adm-pisquare-valid-tag-names] (read)
- Control characters such as linefeeds and tabs are not allowed in tag names. [S:adm-pisquare-valid-tag-names] (read)
- These characters are not allowed in tag names: single quote, double quote, question mark, semicolon, curly braces, square brackets, pipe, backslash, and backtick; they are allowed in other attributes such as the descriptor. [S:adm-pisquare-valid-tag-names] (read)
- The guide says tags "may be any length", but some components impose limits: PI API `pipt_tag` and `pipt_updates` truncate to 12 characters, `pipt_findpoint` reports only the first 80, and "PI SQL Subsystem can only process tags with at most 1016 characters." [S:adm-pisquare-valid-tag-names] (read)
- The guide recommends "a consistent tag-naming convention that is meaningful to people in your organization", with leading characters reserved for a unit or plant area and other characters matching a standard instrument tag. [S:adm-pisquare-valid-tag-names] (read)
- "SQL uses the underscore (_) and percent sign (%) as wild cards", so those characters may cause problems in some applications. [S:adm-pisquare-valid-tag-names] (read)
- A PI Square answer says PI Server "does not support Unicode" in tag names and "stores the raw bits", so readers must use the same non-Unicode OS encoding as the creator. [S:adm-pisquare-unicode-tag-names] (read)
- OSIsoft's AF rollout guidance calls for company naming conventions for both PI tags and AF objects. [S:adm-us19-af-rollout-kwan] [S:adm-uc19-af-batke] (read)
- Templates that auto-create PI Points help "Ensure PI Point naming consistency". [S:adm-us19-af-rollout-kwan] (read)
- Use distinct element names, which are "less confusing for the users" and easier in tabular reporting. [S:adm-uc15-af-batke] (read)
- Element names must be unique within their path; the course recommends unique names across the whole hierarchy and a location code for duplicate device names. [S:adm-building-assets-workbook] (read)
- Renaming AF elements is safe for AF relationships, which use GUIDs, but PI Vision and PI DataLink definitions use element names and need updating. [S:adm-building-assets-workbook] (read)
- The AF default PI Point naming pattern is `%Element%.%Attribute%.%ID%`. [S:adm-building-assets-workbook] (read)
- Vistra Energy's lessons: "Limit and discourage the use of acronyms" and "Naming convention is important for PI Vision". [S:adm-uc19-vistra-cloud] (read)
- Vistra's fleet tags follow a pattern like `DCS_ML1_BM_1B_BOWL_MILL_MTR_IB_BRG_T`, and AF-guided tag creation gave an "Improved and consistent naming convention." [S:adm-uc19-vistra-cloud] (read)
- A PI Square reply suggests a hierarchical name pattern (Country, Region, State, County, Plant, Equipment, EquipmentID, Measurement) and consistent descriptor patterns so wildcard searches work. [S:adm-pisquare-af-attributes-vs-points] (read)
- The UC23 performance deck recommends creating points in bulk during off-hours, because point creation needs a global lock. [S:adm-uc23-da-performance-sick] (read)

**Terms**
- Instrument Tag: point attribute holding the name of the point or location in the source system, which often must match the source exactly [S:adm-arch-planning-workbook-2024]
- Tag naming pattern (AF): the substitution string that builds PI Point names when templates create points [S:adm-building-assets-workbook]

**Worked-example material**
- String Builder pattern for tag names: `"%Element%";".";"%..|Attribute%";` builds names like `FFS01.OEE`. [S:adm-easy-wins-af]
- Tank example: tag names built as `%Element%.%Attribute%` resolve per element, so each Tank gets its own point. [S:adm-building-assets-workbook]

**Common mistakes / pitfalls**
- Inconsistent PI Point names (such as `FFS01SealTemp` vs `02ST3000`) stop substitution from working, so you need manual TagName child attributes or PI Builder. [S:adm-easy-wins-af]
- A PI Square user said their tag naming was "too random (not structured enough)" to use substitution parameters. [S:adm-pisquare-af-table-lookup-10k]
- Using `_` or `%` in tag names causes issues in SQL-based tools. [S:adm-pisquare-valid-tag-names]

**Open questions**
- Whether tag names are case-insensitive is not confirmed in a readable source.
- The current docs.aveva.com statement of tag name rules could not be read.

### adm.af-patterns: AF best practices and anti-patterns

**Facts**
- OSIsoft's first AF commandment is "Thou shalt use Templates"; build every element from a template, even an empty one. [S:adm-us19-af-rollout-kwan] [S:adm-uc15-af-batke] (read)
- Elements built outside a template are not recognised as that asset type in PI Vision and miss template changes; fix by assigning the template and excluding missing attributes. [S:adm-easy-wins-af] (read)
- Use the Excluded attribute property for attributes that do not apply to a given element. [S:adm-easy-wins-af] (read)
- Prefer derived templates for subsets of assets that need extra attributes; disable Allow Extensions on base templates. [S:adm-easy-wins-af] (read)
- The course warns that allowing element-level extra attributes "will no longer guarantee all elements have the same set of attributes." [S:adm-building-assets-workbook] (read)
- Use substitution parameters for portability: server path `%@\Data Archive|Name%` and tag name `%@.|TagName%`, so editing one Data Archive Name attribute repoints all linked attributes during a migration. [S:adm-easy-wins-af] (read)
- Don't rely on the default `%Server%`; point to an explicit configuration attribute, especially when moving from development to production. [S:adm-uc15-af-batke] (read)
- "Defaults are not your friend": write units of measure, formulas and servers explicitly. [S:adm-us19-af-rollout-kwan] [S:adm-uc15-af-batke] (read)
- Always assign a UOM and set Source UOM explicitly; Data Archive EngUnits is a free-text string that is not used in UOM conversion. [S:adm-easy-wins-af] (read)
- "Create or Update PI Point" locks in the resolved name and helps performance on large systems; if TagName changes later, reset to template and repeat it. [S:adm-easy-wins-af] (read)
- Hide helper attributes (for example TagName) and attributes for missing instrumentation so clients don't get errors. [S:adm-easy-wins-af] (read)
- Formula data references slow down with long dependency chains; move the calculation to Asset Analytics and store the result in a PI Point. [S:adm-easy-wins-af] (read)
- Value Retrieval Methods (for example a 90-day average) are computed on the fly by the Data Archive; move them to Asset Analytics too. [S:adm-easy-wins-af] (read)
- Prefer Rollup analyses over Formulas for aggregates; a Formula with a hard-coded unit count fails when an element is deleted. [S:adm-easy-wins-af] (read)
- Import no more than about 10,000 rows into an AF table (rule of thumb); otherwise use parameterised queries. [S:adm-easy-wins-af] (read)
- On PI Square, OSI guidance was quoted as keeping AF tables under 10K rows; since PI 2014 that guideline does not apply to external tables with parameterised queries, because "the selection is done however at server side". [S:adm-pisquare-af-table-lookup-10k] (read)
- For non-external AF tables, "the entire table is loaded into memory on the client". [S:adm-pisquare-af-table-lookup-10k] (read)
- Use enumeration sets for controlled values; since PI Server 2018 SP2 they can be created from digital state sets. [S:adm-easy-wins-af] (read)
- Use expression variables to avoid repeated calculations; the example cut evaluation time from 1.6 ms to 0.6 ms. [S:adm-easy-wins-af] (read)
- Schedule by need: backfilling 6 months at a 1-minute trigger gives 259,200 evaluations vs 180 at daily; offset daily runs from the 12 AM default (for example 1 AM). [S:adm-easy-wins-af] (read)
- Analyses enabled before they are configured correctly are retried by PI Analysis Service every 15 minutes, so disable analyses in Warning or Error. [S:adm-easy-wins-af] (read)
- `Exit()` (2018 SP2+) can skip unneeded evaluations. [S:adm-easy-wins-af] (read)
- Hierarchy: follow a standard such as S95 (Enterprise, Site, Area) and use multiple views with element references for different audiences. [S:adm-uc15-af-batke] [S:adm-us19-af-rollout-kwan] (read)
- Rollout guidance says "Not SAP hierarchy"; a 2019 EMEA deck suggests the ERP hierarchy as a starting point. [S:adm-us19-af-rollout-kwan] [S:adm-uc19-af-batke] (read)
- Vistra Energy: "Strive to keep template count to a minimum" and "Flat hierarchies are easier to maintain." [S:adm-uc19-vistra-cloud] (read)
- Design top-down, then build bottom-up; bottom-up alone "lacks vision", and top-down alone can "drift away from reality". [S:adm-building-assets-workbook] (read)
- Build fewer, larger AF databases, organised by business unit rather than plant, because AF references only work within one database; do not organise assets in the Configuration database. [S:adm-building-assets-workbook] (read)
- Keep relational data in a relational database and link it with AF tables. [S:adm-us19-af-rollout-kwan] [S:adm-uc15-af-batke] (read)
- Imports do not propagate deletions from the master to sites; to match, delete everything and recreate it, then update all data references. [S:adm-us19-af-rollout-kwan] (read)
- Checking in restarts running analytics for affected elements. [S:adm-building-assets-workbook] (read)
- "Our recommendation is to build AF for a single targeted project, using best practices." [S:adm-implementation-adoption] (read)

**Terms**
- Substitution parameter: placeholder such as `%Element%` or `%@.|TagName%` resolved at runtime in data reference configuration [S:adm-easy-wins-af]

### adm.hardening: PI Server security hardening

**Facts**
- The authentication preference order is OIDC (2023+), Windows Integrated Security (Kerberos, then NTLM), PI Trusts, then explicit logins. [S:adm-uc23-security-biggins] (read)
- Avoid "open" trusts that specify only the server name; if a trust is required, apply the 2+ rule: pair the application name with an IP address, host name or FQDN. [S:adm-uc23-security-biggins] (read)
- Explicit logins (PI Users) are disabled by default and not recommended. [S:adm-uc23-security-biggins] (read)
- In PI SMT security settings, disable explicit login, disable explicit login for piadmin, and disable blank passwords, then restart the PI Base Subsystem. [S:adm-uc23-security-biggins] (read)
- Do not use the default piadmin account; give it a password and use the piadmins group instead. [S:adm-uc23-security-biggins] (read)
- "It is not safe practice to map trusts to the piadmin user." [S:adm-arch-planning-workbook-2024] (read)
- Use PI Identities and PI Mappings instead of PI Users and PI Groups, which are kept only for backward compatibility. [S:adm-uc23-security-biggins] (read)
- Minimum permissions: a PI interface needs Read on PIPoint, DBSecurity, PtSecurity and DataSecurity; the PI Buffer Subsystem needs Write on DataSecurity only. [S:adm-uc23-security-biggins] (read)
- PI Buffer Subsystem supports native Windows authentication from version 3.4.380.79; PI API for WIS 2.0.1.35 and later extends Windows authentication to interfaces. [S:adm-uc23-security-biggins] (read)
- After upgrading to PI API for WIS, PI Trust authentication is disabled by default, so replace trusts with mappings first. [S:adm-uc23-security-biggins] (read)
- Windows Integrated Security was introduced with PI Server 3.4.380 (fall 2009). [S:adm-rs2011-wis-bryant] (read)
- "Mappings are cumulative, not exclusive"; PI Trusts allow only one "best fit" association based on a scoring algorithm. [S:adm-rs2011-wis-bryant] (read)
- PI World is the "everyone" identity and PI Demo is a read-only user with no password; once rules are in place, "Disable PI World (identity) and PI Demo (user)." [S:adm-rs2011-wis-bryant] (read)
- The Data Archive records the Active Directory account of administrators in the server log, even when they connect as PIADMIN. [S:adm-rs2011-wis-bryant] (read)
- Install Data Archive on Windows Server 2016–2022 Core to reduce attack surface. [S:adm-uc23-security-biggins] (read)
- Use WDAC on Server 2016–2022 Core and AppLocker (audit mode first) on older or non-Core servers. [S:adm-uc23-security-biggins] (read)
- Anti-virus exclusions should be limited to specific folders for archives, queues and logs; misconfiguration can hurt performance or lose data. [S:adm-uc23-security-biggins] (read)
- Kerberos is recommended over NTLM, which uses weaker encryption and is open to pass-the-hash; Negotiate can fall back to NTLM. [S:adm-uc23-security-biggins] (read)
- PI AF clients attempt Kerberos by default; PI Data Archive WIS accepts SSPI defaults. [S:adm-uc23-security-biggins] (read)
- PI Vision Kerberos checklist: custom service account; run PI Vision as that account; use app-pool credentials under `system.webServer/security/authentication/windowsAuthentication`; create SPNs with `setspn -U -S http/hostname domain\service-account` for both short name and FQDN; delegate the account to the PISERVER and AFSERVER services. [S:adm-uc23-security-biggins] (read)
- Kerberos troubleshooting: check the Data Archive message log for logins; set `LogLevel` REG_DWORD = 1 under `HKLM\SYSTEM\CurrentControlSet\Control\Lsa\Kerberos\Parameters`; run `klist purge` and review the System event log; verify SPNs with `setspn -l` and `setspn -q`; check delegation with `Get-ADUser` and `msDS-AllowedToDelegateTo`. [S:adm-uc23-security-biggins] (read)
- The Data Archive SPN class is `PIServer`, queried with `setspn -q PIServer/<hostname>`; Data Archive Kerberos settings are normally configured automatically at install, though this sometimes fails. [S:adm-pisquare-pivision-collective-tls] (read)
- Firewall table (UC23 deck): Data Archive inbound TCP 5450 from all clients; outbound TCP/UDP 135 (SPN registration), TCP/UDP 88 (Kerberos), UDP 53 (DNS), dynamic ports to domain controllers (NTLM/user lookup), and TCP 5457 to AF for MDB-to-AF sync. [S:adm-uc23-security-biggins] (read)
- AF Server inbound ports: TCP 5457 (AF SDK clients), TCP 5459 (PI SQL for AF clients), TCP 5463 (PI Analysis Service clients), TCP 5468 (PI Notifications Service clients). [S:adm-uc23-security-biggins] (read)
- "Data sent to the Data Archive uses TCP port 5450." [S:adm-it-pros-workbook-2017r2] (read)
- AVEVA bulletins repeatedly advise: "Limit network access to port 5450 to trusted workstations and software." [S:adm-aveva-bulletin-2024-001] [S:adm-aveva-bulletin-2025-001] [S:adm-aveva-bulletin-2026-002] (read)
- AVEVA-2024-001 (CVE-2023-34348, CVSS 7.5; CVE-2023-31274, CVSS 5.3) let an unauthenticated user crash or exhaust the PI Message Subsystem in PI Server 2023 and 2018 SP3 P05 and earlier. [S:adm-aveva-bulletin-2024-001] [S:adm-cisa-icsa-24-018-01] (read)
- AVEVA-2024-001 also advises restricting write access to the Message Log via the PIMSGSS entry in Database Security, auto-restarting the PI Message Subsystem and monitoring its memory. [S:adm-aveva-bulletin-2024-001] (read)
- AVEVA-2025-001 (CVE-2025-44019, CVE-2025-36539) is a Data Archive denial of service; CVE-2025-44019 can lose "data present in snapshots/write cache". [S:adm-aveva-bulletin-2025-001] [S:adm-cisa-icsa-25-162-07] (read)

- AVEVA's bulletin page also lists PI Web API (2024-003, 2025-003), PI AF Client (2024-004), PI Integrator for BA (2025-004) and PI to CONNECT Agent (2026-003) bulletins. [S:adm-aveva-cyber-updates-page] (read)
- AVEVA bulletins reference KB01162 (firewall port requirements) and KB00833 (PI Server security best practices). [S:adm-aveva-bulletin-2024-001] (read)
- A 2010 deck recommended the tuning parameter `AutoTrustConfig` be set to 0. [S:adm-vl2010-optimization] (read)

### adm.troubleshooting: logs, error codes, playbooks

**Facts**
- The PI Message Log is read with PI SMT, the PI SDK Utility, or `pigetmsg`. [S:adm-uc23-da-performance-sick] (read)
- `pigetmsg -f` follows the message log; run it from `PIHOME\adm` on clients or `%piserver%\adm` on the Data Archive. [S:adm-pisquare-piputval-11414] (read)
- A thread dump of the archive subsystem: `cd /d %piserver%adm` then `piartool -thread piarchss -info`. [S:adm-uc23-da-performance-sick] (read)
- An RPC duration over 1000 ms is generally considered long. [S:adm-uc23-da-performance-sick] (read)
- Message ID 2016 "Inserting overflow record" indicates backfilling or out-of-order writes. [S:adm-uc23-da-performance-sick] (read)
- "Heavy hitter" messages: [-11091] event collection limit exceeded; [-11140] query exceeded maximum execution time; [-10767] client exceeded concurrent queries in the RPC thread pool. [S:adm-uc23-da-performance-sick] (read)
- `ArcMaxCollect` limits compressed events per query and defaults to 1.5 million; `Archive_MaxQueryExecutionSec` limits query run time and defaults to 260 seconds. [S:adm-uc23-da-performance-sick] (read)
- Use the Connection ID from those messages or thread dumps to find the client in Network Manager Statistics. [S:adm-uc23-da-performance-sick] (read)
- `piarchss_ThreadCount`: "Number of cores – 1" for standard use, "2X number of core" for large queries without real-time users; `Archive_ReprocessThreadCount` = 1 for 2018 SP2 and later. [S:adm-uc23-da-performance-sick] (read)
- Point creation and deletion update the Point Table, Snapshot Table and primary archive under a global lock, so run them off-hours. [S:adm-uc23-da-performance-sick] (read)

**Worked-example material: troubleshooting playbook (decision trees)**

*Tag not updating*
1. Is the source providing data? Check with a source tool (for example the PI OPC Client Tool). [S:adm-pdfcoffee-pi-sys-admin-2018sp2]
2. Is the interface healthy? Check IO Rate (stopped means no collection) and Device Status (GOOD); Heartbeat alone isn't enough. [S:adm-it-pros-workbook-2017r2]
3. Do the point attributes match? Check Instrument Tag (exact, often case-sensitive), Point Source, Location1 (/ID) and Location4 (scan class). Read the interface startup message about matching points. [S:adm-pdfcoffee-pi-sys-admin-2018sp2]
4. Is buffering stuck? Run `pibufss -cfg` and `pibufss -qs`. [S:adm-it-pros-workbook-2017r2]
5. Are permissions or mapping missing? Look for -10401 (no write access) or -11414; check the identity in Network Manager Statistics and point DataSecurity. [S:adm-pistatus-h] [S:adm-pisquare-piputval-11414]
6. Are clocks off? Data over 10 minutes in the future is discarded, and an interface 30 minutes off won't run (-11046 target date in future). [S:adm-arch-planning-workbook-2024] [S:adm-pistatus-h]
7. Is it Data Archive side? Use `piartool -ss`, `-qs` and `-as` (archiving flag 3, reads and writes moving together). [S:adm-pdfcoffee-pi-sys-admin-2018sp2]
8. Is it filtered? Values within exception or compression deviation are not stored. [S:adm-it-pros-workbook-2017r2] (inferred)

*Cannot connect to Data Archive*
1. Network: ping both ways, then test TCP 5450 (`Test-NetConnection` or the tcpclient one-liner). [S:adm-pdfcoffee-pi-sys-admin-2018sp2] [S:adm-tdengine-pi-prereqs]
2. Client stack: `apisnap <server>` for PI API, and AboutPI-SDK for PI SDK. [S:adm-it-pros-workbook-2017r2]
3. Authentication: check the message log for failed logins, then mappings (the usual cause) and trusts. [S:adm-uc23-security-biggins] [S:adm-arch-planning-workbook-2024]
4. Kerberos: `setspn -q PIServer/<host>`, Kerberos logging and `klist purge`. [S:adm-pisquare-pivision-collective-tls] [S:adm-uc23-security-biggins]
5. TLS: `pidiag -tls --verify`; message ID 748 means no certificate loaded. [S:adm-pisquare-pivision-collective-tls]
6. Timeouts: -10722 (PI_NET_TIMEOUT) and -10010 (PI_ERR_TIMEOUT) are timeout codes. [S:adm-pistatus-h]

*PI Vision display slow*
1. Look for heavy hitters in the Data Archive log: -11091, -11140, -10767; find the client by Connection ID. [S:adm-uc23-da-performance-sick]
2. Check RPC durations (over 1000 ms is long). [S:adm-uc23-da-performance-sick]
3. Check on-demand calculations: PI Vision 2020+ runs simple calculations on the Data Archive; see the PI Vision Admin site, Reports > Calculation usage. [S:adm-uc23-da-performance-sick]
4. Move Formula and Value Retrieval Method data references to Asset Analytics. [S:adm-easy-wins-af]
5. Check storage latency, archive files against RAM, and point expensive clients at a collective secondary. [S:adm-uc23-da-performance-sick]

*Analysis not calculating*
1. Is the analysis in Warning or Error? The service retries every 15 minutes; fix the configuration and re-enable. [S:adm-easy-wins-af]
2. Can the service reach AF? AF port 5463 serves PI Analysis Service clients. [S:adm-uc23-security-biggins]
3. Is the output point writable by the Analysis Service identity? Look for -10401. [S:adm-pistatus-h] [S:adm-imd-af-analysis-table-lookup]
4. For Table Lookup inputs, the scheduled run uses the Analysis Service account, not the engineer's, so check its database rights (third-party, unverified). [S:adm-imd-af-analysis-table-lookup]
5. Is the trigger wrong? Check the schedule against need, and remember Preview runs client-side. [S:adm-easy-wins-af]
6. Was a check-in pending? Check-in restarts analyses. [S:adm-building-assets-workbook]

**Common mistakes / pitfalls**

### adm.dr-migration: backup, HA, migration

**Facts**
- "PI Backups, Redundant Interfaces and High Availability are NOT stand-alone Disaster Recovery solutions." [S:adm-uc19-architecting-zhimanov] (read)
- Run a DR simulation at least once a year. [S:adm-uc19-architecting-zhimanov] (read)
- 99.9% uptime allows about 43.8 minutes downtime per month, or 8.76 hours per year. [S:adm-uc19-architecting-zhimanov] (read)
- Schedule daily backups off-peak with Windows Task Scheduler, back up locally, then copy to a separate server or network drive (two-phase strategy for ransomware recovery). [S:adm-uc23-security-biggins] (read)
- PI Backup uses VSS, so it can back up files in use without downtime. [S:adm-pisquare-piartool-collectives] (read)
- `piartool` archive registration is per host: "You need to run piartool on the PI Data Archive host which you want to modify the archive registration on." [S:adm-pisquare-piartool-collectives] (read)
- Archives are independent on each collective member; only some configuration replicates from primary to secondaries. [S:adm-pisquare-piartool-collectives] (read)
- PI Collective Manager synchronises a secondary by taking a PI Backup of the primary, copying it and registering it. [S:adm-pisquare-piartool-collectives] (read)
- Use PI Buffer Subsystem on interface nodes to fan data out to all collective members. [S:adm-pisquare-piartool-collectives] (read)
- The primary archive cannot be unregistered and has no end time. [S:adm-it-pros-workbook-2017r2] (read)
- Each archive's `.ann` annotation file must stay in the same directory as the archive. [S:adm-it-pros-workbook-2017r2] (read)
- Moving archives: force an archive shift, unregister, move `.arc` and `.ann`, then re-register. [S:adm-it-pros-workbook-2017r2] (read)
- Keep at least 2 empty historic archive files. [S:adm-it-pros-workbook-2017r2] (read)
- Collective members should be identical and can be in different data centres. [S:adm-implementation-adoption] (read)
- Moving a Data Archive to new hardware means installing the same version and restoring from backup. [S:adm-feedback-pida-i-1108] (read)
- For AF migration across environments, use substitution parameters (`%@\Data Archive|Name%`) so one attribute change repoints data references. [S:adm-easy-wins-af] (read)
- AF HA options include AF behind a Network Load Balancer with SQL on separate redundant computers. [S:adm-arch-planning-workbook-2024] (read)
- In Azure deployments, restoring a VM from disk snapshots is much faster than redeploying, but snapshots are large, not portable, and must restore to the same environment. [S:adm-uc19-azure-deploy-pdf] (read)
- Use a PI Collective for HA and point expensive clients at the secondary. [S:adm-uc23-da-performance-sick] (read)

**Terms**
- PI Collective: set of Data Archive servers (primary and secondaries) with replicated configuration [S:adm-pisquare-piartool-collectives]
- Primary archive: the archive currently receiving data, with no end time [S:adm-it-pros-workbook-2017r2]
- VSS: Windows Volume Shadow Copy Service used by PI Backup [S:adm-pisquare-piartool-collectives]

**Common mistakes / pitfalls**
- Treating HA or backups as the DR plan. [S:adm-uc19-architecting-zhimanov]
- Expecting `piartool` run once to change archives on every collective member. [S:adm-pisquare-piartool-collectives]
- Leaving backups only on the same server. [S:adm-uc23-security-biggins]

**Open questions**
- Exact `piartool -backup` syntax and `pibackup` script options were not readable.
- SQL AlwaysOn support for AF versions was not confirmed.

### sec.iec62443: IEC 62443

**Facts**
- IEC 62443 clusters: 1-x general; 2-x policies and procedures (2-1 asset owner programme, 2-3 patch management, 2-4 service providers); 3-x system (3-2 zones and conduits risk assessment, 3-3 system requirements); 4-x component (4-1 secure development process, 4-2 component technical requirements). [S:adm-iec-62443-background] (read)
- "A zone is a grouping of assets based on risk"; communication between zones runs through "conduits". [S:adm-iec-62443-background] (read)
- The standard "defines four security levels (SL1, SL2, SL3, SL4)" correlating countermeasures with adversary strength. [S:adm-iec-62443-background] (read)
- Foundational requirements: FR1 identification and authentication control, FR2 use control, FR3 system integrity, FR4 data confidentiality, FR5 restricted data flow, FR6 timely response to events, FR7 resource availability. [S:adm-iec-62443-background] (read)
- A vendor explainer defines SL1 casual or coincidental violation; SL2 intentional, simple means; SL3 intentional, sophisticated means; SL4 sophisticated with extended resources; and SL-T (target), SL-C (capability), SL-A (achieved). [S:adm-trout-zones-conduits] (read)
- AVEVA states its SDL is "compliant with the ISA/IEC 62443-4-1 standard" and "has achieved ISASecure SDLA Certification." [S:adm-aveva-hmi-scada-security-wp] (read)
- AVEVA recommends segmenting the network and separating zones with firewalls and virtual network technology, following defence in depth. [S:adm-aveva-hmi-scada-security-wp] (read)
- Mapping PI to 62443 (inferred): a PI to PI link or a one-way gateway between the control-network Data Archive and a DMZ or business Data Archive is a conduit; FR5 (restricted data flow) is met by data-only or one-way designs. [S:adm-uc19-architecting-zhimanov] [S:adm-iec-62443-background] (inferred)

**Open questions**
- No readable source confirmed an ISASecure CSA or 62443-4-2 certification for PI Server itself; only AVEVA's SDLA (4-1 process) certification was found.

### sec.nerc-cip: NERC CIP

**Facts**
